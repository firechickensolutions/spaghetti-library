# Salesforce learning project

- Verify that the starter, both skills, and packaged assets are readable. Ask which tools are already installed and which step is complete. Explain one action, its window/folder, and its expected result; wait for the learner before continuing. The first-time walkthrough is at `../../../FIRST-TIME-SETUP.md` relative to this skill folder.
- Start with the learner’s OS and available practice org. Offer Developer Edition if they need an org. Use synthetic data in a confirmed learning org. Guide browser sign-in without asking for passwords, MFA codes, access tokens, or authentication URLs.
- Teach the route from Setup to source files. Objects and fields describe the work, Lightning App Builder places and configures a component, and permissions and sharing determine what it can display. Ask which parts Salesforce configuration already solves.
- Use [setup](references/setup.md) for tools, an explicit learning-org alias, and a new local Salesforce DX project. Verify the installed `sf` commands and API 68.0 support before deployment.
- Use the [Related Activity Board walkthrough](references/first-lwc.md) and its [packaged LWC](assets/relatedActivityBoard/) for the first deployment. Explain Task status, the Related To relationship, and the board’s allowlisted Case fields. The exercise adds a read-only app page alongside standard views. Use `dev-baseline` before changing code.
- Generate the local project, then apply the four [test-tooling files](assets/test-tooling/) to the fresh standard lab before its first package install. Preserve any existing customization. Use `npm ci --ignore-scripts` with the supplied lockfile, require a zero-finding full `npm audit`, and run all twelve component tests, the two toolchain regressions, and lint before any deployment. Keep upstream deprecation notices visible and distinct from security advisories. A learner without an org can finish these local steps; distinguish them from the still-pending live checks.
- Preview and validate only the supplied bundle. Confirm the target and change with the learner before applying metadata, page activation, or permission edits. Follow pending jobs by ID. Start the practice page with administrator-only activation, then assign only the specific test audience needed. Follow the walkthrough’s separate field, object, and record-sharing checks as a dedicated non-admin user. Check profile page-layout assignments as well as data permissions. Restore temporary login settings and retire temporary test access. Save local test outcomes and any pending org checks; the pack’s completed rehearsal does not replace checks for the learner’s org.
- For an exercise involving Apex, custom data access, or permission metadata, read [permissions, Apex, and tests](references/permissions-and-apex.md).
- For a proposed release beyond the learning org, read [production readiness](references/production-readiness.md) before planning validation, rollout, and recovery.
